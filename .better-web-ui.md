# Vibebook — Design Context

> Canonical design context for all future UI work. Created in **I1** (2026-11-08)
> from the product plans, the existing app, and the three identity directions.
> The recommended direction is **Verdín**; the alternatives are kept here until
> the user approves one. No implementation should start from a different context.

## Design Context

### Users

**Primary:** Spanish-speaking readers in Latin America (25–55) who own EPUBs and
want a private, local library that can also become an audiobook. They read on a
laptop or desktop at home, often in the evening, and may listen while commuting
or doing chores. They are not necessarily technical, but they are willing to
install a desktop app if it respects their files and works offline.

**What they are trying to do:**

1. Import an EPUB and see it on a shelf immediately.
2. Open it and read without converting anything first.
3. Optionally convert it to audio and listen with synced text.
4. Keep their place, bookmarks, and reading preferences per book.
5. Add ambience later, without it becoming mandatory or cloud-dependent.

**Secondary audience:** open-source contributors and tinkerers who self-host,
care about licenses, inspect the engine registry, and may add a VEP plugin.
They should find a product that feels cared for, not a developer dashboard.

**Accessibility:** keyboard-first navigation, visible focus, screen-reader
landmarks, reduced motion, high contrast, and a text mode that is genuinely
comfortable (not a fallback). Dyslexia-friendly font option must remain.

**Non-goals:** accounts, social features, a storefront, cloud sync as a
requirement, productivity metrics, or a chat/assistant surface.

### Brand Personality

**Three words:** serena, erudita, precisa.

- **Serena:** calm surfaces, quiet motion, no urgency, no growth prompts.
- **Erudita:** bookish details, catalogue numbers, folios, colophons, real
  titles; knowledge without academic coldness.
- **Precisa:** exact labels, honest states, measurable sync, no fake progress.

**Voice:** conversational Rioplatense Spanish, warm but not cute. Short labels,
concrete verbs, no hype. “Tu biblioteca, tu máquina” is the promise; “modo
local” is a visible fact, not a badge.

**Emotional goal:** the quiet ownership of a personal reading room. Delight
comes from small, legible craft — a ribbon, a spine, a brass rule — not from
neon, glass, or decoration that competes with the text.

### Aesthetic Direction

**Recommended: Verdín.** A day-and-night personal library: cool paper,
verdigris green, brass details, dark wood at night. Display in Spectral, reading
in Literata, UI in Public Sans, metadata in IBM Plex Mono. Radii 2–6 px, 1 px
rules, soft static shadows, shelf lines, cloth covers, and a “lomo + onda” mark.
It is bookish without imitating old paper.

**Alternatives, only for I1 comparison:**

- **Señal:** ink + cobalt + amber, Archivo / Source Serif 4. A catalogue-card,
  field-notes library: technical, graphic, precise.
- **Nocturno:** plum + amber, Bodoni Moda / Crimson Pro. A dramatic reading
  room: high contrast, deep margins, nocturnal but not neon.

**References:** wooden reading rooms, brass library lamps, hardcover cloth
bindings, catalogue cards, library stamps, folios, index tabs, book spines,
marbled endpapers (used sparingly).

**Anti-references (do not ship):**

- cream `#f4efe5` + terracotta `#a94e36` + Fraunces as the default identity;
- generic “old paper” beige, faux parchment, sepia filters everywhere;
- glassmorphism, blur panels, frosted cards, glow borders;
- violet-to-blue gradients, neon on dark, cyber/terminal aesthetics;
- Three.js, WebGL, decorative canvas, heavy full-screen noise;
- generic dashboard cards, hero-metric layouts, identical card grids;
- AI-assistant or chat-panel visual language;
- pure black `#000` or pure white `#fff` as the base.

**Theme model:** the app and the reader are separate lights. `theme_mode`
(`system | light | dark`) controls the whole app; `reader_palette`
(`paper | sepia | night`) controls only the reading surface. A dark app can have
a paper reader, and a light app can have a night reader. No flash on reload.

**Motion:** quiet, 120–320 ms, exponential ease-out. Only `transform` and
`opacity` for page turns and reveals. No parallax, no continuous ambient motion,
no layout-property animation. Reduced motion removes the page turn, not the
content.

**Imagery:** CSS-generated covers and spine treatments for missing artwork;
real covers lazy-loaded, never upscaled beyond their source. No full-screen
texture images, no background video, no decorative WebGL.

### Implementation Defaults

Detected in the existing project; preserve unless the user explicitly changes
them:

- **Framework:** React 19 + Vite 8 + TypeScript 7.
- **Styling:** vanilla CSS with custom properties, imported in `main.tsx`;
  no Tailwind, no CSS-in-JS.
- **Components:** local components + Radix Dialog; `lucide-react` icons at
  stroke 1.8. Do not introduce a second icon set.
- **Data/state:** TanStack Query + React Router 7. Preserve the existing
  query/mutation patterns.
- **Fonts:** production uses Fontsource packages (not a Google Fonts runtime
  link). Verdín adds Spectral and Literata; keep Public Sans and IBM Plex Mono.
  Load only latin/latin-ext subsets, 400/500/600, `font-display: swap`. Preload
  display + UI; load Literata on entering the reader.
- **Theming:** `data-theme` on `<html>`; `data-reader-palette` on the reader
  shell. Anti-flash script in `web/index.html`. Old `reader_theme` migrates to
  `reader_palette`; old manifests/API fields keep working.
- **Performance:** initial JS ≤ 550 KiB gzip, CSS ≤ 60 KiB; reader open ≤ 1.5 s;
  no WebGL/Three.js; no full-screen noise; page-turn 60 fps.
- **Accessibility:** WCAG AA (4.5:1 normal, 3:1 large), keyboard/focus,
  `prefers-reduced-motion`, `forced-colors`, axe with no serious/critical.
- **Assets:** local, open-licensed, no paid API required. CC0/procedural
  ambience; plugins are opt-in and marked.

**Precedence when future work is ambiguous:** existing project stack → explicit
user decision → framework defaults. Do not replace the stack silently.

### Design Principles

1. **The book is the interface.** Lead with the title, the text, and the next
   action. Chrome recedes; the reader never looks like a dashboard.
2. **Calm is a system, not a color.** Build hierarchy with spacing, weight,
   scale, and 1 px rules first; add green, brass, and shadow only after the
   grayscale layout works.
3. **Two lights, one product.** App theme and reader palette are independent.
   Every surface must be designed in light and dark, and the reader must work
   in paper, sepia, and night without changing the app shell.
4. **Craft lives in the margins.** Spine labels, folios, catalogue numbers,
   ribbons, and colophons are small, functional details. Use one or two per
   screen, never as wallpaper.
5. **Performance is part of the aesthetic.** No blur, WebGL, full-screen
   textures, or animating layout. A fast, quiet interface is the brand.
6. **Local trust is visible.** Show “modo local”, exact states, and honest sync.
   Never hide a required account, a paid service, or a destructive action.
