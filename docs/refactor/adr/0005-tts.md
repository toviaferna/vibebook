# ADR-0005 — TTS local: sherpa_onnx/Piper; Kokoro con spike

- **Estado:** Propuesto; pendiente G2 para Kokoro.
- **Fecha:** 2026-11-17.

## Contexto

Vibebook usa Piper, Kokoro, eSpeak y proveedores cloud. En Flutter no hay un
runtime Python; el TTS local debe correr en Dart/nativo. Kokoro español es el
caso más difícil: el modelo es multilingüe, pero los modelos convertidos de
sherpa-onnx solo agregan inglés/chino.

## Decisión

- **Piper/VITS:** `sherpa_onnx` 2.0.1 en todas las plataformas.
- **Kokoro:** spike con `flutter_onnxruntime` + G2P español; si no alcanza,
  mantener Kokoro solo en desktop vía Python embebido o reemplazarlo por
  Piper/cloud con aprobación.
- **eSpeak/sistema:** `flutter_tts` como fallback, no motor principal.
- **Cloud:** clientes Dio/WebSocket por proveedor; `edge_tts` (MIT) vendorizado
  como referencia.
- **Contrato:** `EngineSpec`/`TtsEngine`/`TtsRequest`/`AudioResult` estable.

## Alternativas

- `kokoro_tts_flutter` / `flutter_kokoro_tts`: baja adopción; no se adoptan sin
  spike.
- `flutter_onnxruntime` para todo: más control, más trabajo.
- Python embebido para TTS: conserva paridad, pero mantiene runtime.

## Consecuencias

- Piper español funciona en todas las plataformas.
- Kokoro puede quedar condicionado; se documenta.
- Timings: exactos en cloud; estimados por palabra en local.
- Modelos se descargan aparte con checksum.

## Criterios de revisión

- F0: Kokoro español inteligible y RTF aceptable.
- Tests de contrato por motor.
- Sin claves en logs.
